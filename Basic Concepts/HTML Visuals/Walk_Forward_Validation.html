09Formula Reference
CAGR
CAGR = (V_final / V_start)^(252/N) − 1
N = number of trading days in the period; 252 trading days/year is assumed.
Sharpe Ratio (annualized)
Sharpe = mean(daily returns) / std(daily returns) × √252
Assumes a zero risk-free rate for simplicity.
Maximum Drawdown
MaxDD = max over t of (running peak equity − equity(t)) / running peak equity
Turnover
Turnover = Σ |position(t) − position(t−1)|
A position of 1 unit fully reversing to −1 contributes 2 to turnover.
Signal & Position Timing
signal(t) = 1 if MA_fast(t) > MA_slow(t) else 0 (or −1 if shorts allowed)
position held on day t+1 = signal(t); return(t+1) uses that position
The one-day lag between signal and execution avoids lookahead bias — today's trade can only use information known as of yesterday's close.
10Overfitting, Data Snooping & Why Walk-Forward Testing Exists
Overfitting & Data Snooping

Overfitting happens when a strategy's parameters are tuned so closely to the quirks of one specific dataset that they capture noise rather than a genuine, persistent pattern. Data snooping (or "data mining bias") is the related risk of testing many parameter combinations against the same data until one happens to look great by chance — with enough combinations tried, some will look spectacular purely by luck, not skill.

The Parameter Performance Heatmap above makes this concrete: a smooth surface where many nearby parameter combinations perform similarly suggests a robust pattern; a sharp, isolated peak surrounded by mediocre neighbors is a warning sign that the "best" combination may just be noise.

Parameter Instability

If the truly "best" parameters were stable properties of the market, walk-forward optimization should select roughly the same parameters window after window. In practice, the Parameter Selection Through Time chart usually shows the selected (fast, slow) pair jumping around, often correlating with regime shifts — what worked during a trending window can be actively harmful once the market turns choppy or reverses. That instability is itself important information, not a flaw in the tool.

Why Walk-Forward Testing Is More Realistic

Selecting parameters by optimizing over the entire historical dataset and then reporting performance over that same dataset is a form of look-ahead bias: you are effectively trading with knowledge of the future. Walk-forward testing enforces a stricter, more honest discipline: parameters are chosen using only data available up to a point in time, then judged strictly on data that follows — exactly mirroring how a strategy would actually have to be run in real time, without the benefit of hindsight.

The Metrics Comparison table above typically shows the full-sample, hindsight-optimized result looking better than the honest walk-forward result. That gap is not a bug — it is the lesson: it's a direct, visible measure of how much of the full-sample result was really just overfitting to that specific history.
